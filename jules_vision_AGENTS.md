# 🤖 Jules Vision: Инструкции для ИИ-агентов (AGENTS.md)

Привет, будущий ИИ-агент! Этот файл содержит ключевую информацию и правила работы в репозитории `mailru-mcp-server`. Изучи их перед началом работы, чтобы не совершать критических ошибок.

## 1. Стек и зависимости
Проект представляет собой stateless Model Context Protocol (MCP) шлюз, написанный на **Python**.
Ключевые зависимости (указаны в `requirements.txt` и коде):
- `mcp[cli]` (используется `FastMCP` для создания сервера)
- `imap-tools` (для работы с почтой по IMAP)
- `webdavclient3` (для работы с облачным хранилищем WebDAV)
- `pydantic` (для валидации данных)
- Стандартные библиотеки Python (`email`, `imaplib`, `smtplib`, `uuid`)

## 2. Команды верификации
Перед сдачей работы (открытием PR) обязательно запускай проверки, чтобы убедиться в работоспособности кода.

- **Проверка синтаксиса:**
  ```bash
  python -m py_compile src/*.py
  ```
- **Локальный запуск сервера:**
  Поскольку сервер требует секретов и мгновенно падает (Fail-Fast) при их отсутствии, запуск должен осуществляться строго через обертку, инжектящую секреты в память:
  ```bash
  with-secret <VAULT_POINTER> --env MAILRU_APP_PASS -- python src/server.py
  ```

## 3. Архитектурные особенности и правила кодинга
- **Управление секретами (CRITICAL):** Запрещено хардкодить пароли и API-ключи. Запрещено использовать файлы `.env`. Все креды передаются через переменные окружения при запуске (Vault Protocol).
- **Двухфазный коммит (HITL):** Все деструктивные или мутирующие действия (отправка email, удаление файлов, создание папок) защищены Human-In-The-Loop. Инструмент (например, `mail_send_reply`) лишь регистрирует намерение в оперативной памяти и возвращает токен. Выполнение происходит только после подтверждения пользователем через вызов `execute_pending_action(token)`.
- **Stateless-архитектура:** Сервер не хранит персистентного состояния о CRM-сущностях (сделки, задачи). Токены отложенных действий хранятся просто в словаре в RAM (`PENDING_ACTIONS`).
- **Защита от контекстного переполнения:** Все функции чтения (`mail_read_inbox`, `dav_list_dir`) строго ограничивают количество возвращаемых записей (жесткие лимиты, пагинация, обрезка текста сниппетов).
- **Соглашение об именовании (WebDAV):** Директории создаются в формате `Имя_Клиента__UUIDv7` (например, `ООО_Вектор__c_0192f4c1`) для избежания коллизий имен.

## 4. Советы для будущих ИИ-агентов
- **Не трать время на CardDAV/CalDAV:** В текущей реализации `master` API для контактов и календаря Mail.ru не работает (ошибки 500, таймауты) из-за проприетарных особенностей. Эти протоколы отключены в Production. Экспериментальный код лежит в ветке `agent/trickster-dav-expansion`.
- **Рабочий процесс (GitHub Flow):** Прямые пуши в `master` заблокированы. Все изменения делай в новых ветках с префиксами `jules/` или `agent/`.
- **Защита HITL:** Никогда не убирай механизм двухфазного подтверждения из мутирующих функций в угоду "автономности". Это сломает гарантии безопасности проекта.
- **Ошибки инициализации:** Если ты видишь ошибку `CRITICAL STARTUP FAILURE`, проверь переменные окружения — сервер настроен на Fail-Fast, он не должен работать в частично сломанном состоянии.

# 🤖 Доктрина для ИИ-агентов (jules_vision_AGENTS.md)

Добро пожаловать в репозиторий Mail.ru MCP Server. Этот файл содержит ключевые инструкции, архитектурные правила и советы для эффективной и безопасной работы автономных ИИ-агентов в данном проекте.

## 1. Стек и зависимости
Проект представляет собой stateless шлюз Model Context Protocol (MCP) на Python.
- **Язык программирования:** Python 3.x
- **Основной фреймворк:** MCP SDK (`mcp.server.fastmcp` >= 1.0.0)
- **Работа с почтой (IMAP/SMTP):** `imap-tools` (>= 1.6.0)
- **Работа с облаком (WebDAV):** `webdavclient3` (>= 3.14.6)
- **Валидация данных:** `pydantic` (>= 2.0.0)

## 2. Команды верификации
Перед каждым коммитом и открытием Pull Request (PR) агент обязан выполнять проверки:

- **Проверка синтаксиса (Обязательно):**
  ```bash
  python -m py_compile src/*.py
  ```
- **Запуск линтеров и форматирования (Рекомендуется, если установлены):**
  ```bash
  black src/
  flake8 src/
  ```
- **Тестовый запуск сервера (с использованием Vault Protocol):**
  ```bash
  with-secret <VAULT_POINTER> --env MAILRU_APP_PASS -- python src/server.py
  ```
*(Никогда не запускайте сервер без `with-secret`, так как он завершится с ошибкой из-за паттерна Fail-Fast)*

## 3. Архитектурные особенности и правила кодинга

- **Безопасность секретов (Vault Protocol):** КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО сохранять пароли и API-ключи в `.env` файлы или зашивать в код (хардкод). Секреты всегда передаются в память через обертку `with-secret`.
- **Stateless (Без состояния):** MCP-сервер не использует локальные БД (например, SQLite) для хранения логики CRM. Любые состояния хранятся на стороне вызывающих агентов (TheNovaNodes).
- **Fail-Fast инициализация:** При старте сервера без нужных кредов приложение падает сразу (`exit 1`), а не скрывает ошибку.
- **Human-In-The-Loop (Двухфазный коммит):** Любые мутирующие или деструктивные действия (отправка писем R3, удаление файлов R4) блокируются. Генерируется UUID токен, который сохраняется в RAM. Для выполнения действия необходимо вызвать `execute_pending_action(token)`.
- **Пагинация и защита контекста:** Лимитируйте количество запрашиваемых писем и файлов для защиты от переполнения контекста LLM.
- **Структура директорий WebDAV:** Строго `Имя_Клиента__c_UUIDv7` (например: `ООО_Вектор__c_0192f4c1`).

## 4. Советы для будущих ИИ-агентов (Ограничения)

1. **Ветвление:** Прямые пуши в ветку `master` запрещены! Всегда создавайте ветки с префиксом `jules/` или `agent/` и вносите изменения через Pull Request.
2. **Игнорируйте CalDAV и CardDAV в master:** Не пытайтесь исправлять или реализовывать функционал работы с календарями и контактами в ветке `master`. Они не поддерживаются из-за проприетарных особенностей API Mail.ru (для этого есть отдельная ветка `agent/trickster-dav-expansion`).
3. **Патчи безопасности:** Любые security-исправления должны быть **до 50 строк кода**, не ломать обратную совместимость (no breaking changes) и обязательно сохранять логику HITL (Human-In-The-Loop).
4. **Sentinel-логирование:** При обнаружении критических уязвимостей, документируйте их в файл `.jules/sentinel.md` в строгом формате:
   ```markdown
   ## YYYY-MM-DD - [Title]
   **Vulnerability:** [What you found]
   **Learning:** [Why it existed]
   **Prevention:** [How to avoid next time]
   ```
